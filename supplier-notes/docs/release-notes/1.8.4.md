# HiveMind 1.8.4

More fixes for saving when another program briefly keeps HiveMind's files busy (antivirus, the
Windows search indexer, a sync or backup tool). Your notes, settings and API keys carry over from
1.8.3.

## Fixed

- If the latest changes could not be saved when you close HiveMind, it now tells you and stays open
  unless you choose **Close without saving**. Before, it closed and the changes since the last
  successful save were lost without a message. Closing again tries to save once more.
- A data file that is briefly busy when HiveMind starts no longer puts the app in recovery mode.
  HiveMind waits and tries again for up to five seconds, also when it reads the file before a save
  or a backup.
- A save no longer fails because of the small lock file HiveMind creates next to the data file, and a
  save that was written is no longer reported as failed when that lock file could not be removed.
- "Automatic backup failed" no longer appears when the new backup was made and only an old backup
  could not be removed. A backup folder that cannot be read no longer stops later backups or the app
  from starting.
- The "Automatic backup failed" message disappears by itself when the next backup works.
- Failed saves are written to the log file (`%APPDATA%\supplier-notes\logs\hivemind.log`), and the
  log keeps being written when the previous log file cannot be replaced.

HiveMind is not code-signed. Windows SmartScreen may show "Windows protected your PC" for a new
version; choose **More info → Run anyway**.

Download **HiveMind-Setup-1.8.4.exe** below to install or update the Windows app.
